GreenStreets component library

The components of the Figma library GreenStreets Component Page — the source of truth for this page: only what that file shows is catalogued here, under its names and in its order. Each one is rendered by the actual prototype stylesheets and carries the markup that produces it, the classes to port, the stylesheet it lives in, and links to the pages it appears on. Components the Figma library does not carry are archived in old/components-all.html.

One specimen per style, base elements first. Anything labelled Base is one component with one class contract — port it as a component. Composed means base elements plus typography, carrying no CSS of its own — port it as a pattern, and its parts are listed as links. Where the codebase has several classes for the same style, only one appears here and the tooltip names the rest. Hover the i for the rules; hover a specimen for Copy.

Porting notes. These prototypes are vanilla HTML/CSS/JS with no build step, so behaviour that a React port would express as component state is currently a class toggle plus a global function (.on, .open, .active, go('sN')). Treat the markup + class contract as the spec and the inline onclick as a note about intent. Where a component is generated by JS rather than authored (data grids, AI review fields, packaging detail sections, tour bubbles), the specimen shows the DOM shape that JS produces and the tooltip names the file that produces it.

Typography

There is no h1–h6 scale here — headings are components (.pg-title, .grp-hdr, .sec-lbl). Keep the HTML heading level correct for the outline and let the class carry the size.

Buttons

One card per button, each with its own component file. Size, icon, disabled and loading are props rather than separate cards — a small primary is the same style as a large one — so each card's Usage column shows them. Everything else in the codebase that looks like a further button is .btn-g renamed; the tooltips name the duplicates.

Form inputs

One primitive, .fi, wrapped by .fgrp (label + control + hint). Native <select> popups cannot be themed, so the theme JS swaps every select.fi for a themed one and keeps the real element for its value — the selects below are those replacements.

Selection controls

The checkbox is the one selection control in the library. Native checkboxes are restyled (dark fill, green when checked) so every listing looks the same.

Alerts & feedback

Banners for standing conditions, toasts for what just happened, a one-time coach hint for the data grid's keyboard model, and an inline marker for out-of-scope controls. Each one says what is wrong and what to do about it.

Cards & surfaces

One glass surface — translucent fill, 1px border, backdrop blur — shaped for different payloads. .grp is the workhorse; the stat card is the same recipe.

Tables & data grid

A plain table.tbl. Rows become clickable only when there is somewhere for them to go, and a selected row carries the accent bar on its leading edge.

Pills & badges

Status is the most repeated idea in the product. The rule: a status is always a pill with a word in it — never a bare dot, never colour alone.

Progress & steps

Compliance is a completion problem, so most screens answer “how far along is this?”. The meter always pairs the bar with the raw figures.

App shells

The chrome a page sits in: the impersonation banner across the top, a row of the left navigation pane, and the component chips — with the dashed button that closes their list — that hang packaging components off a product.

Scrollbar

Used on the right section of each page. The bar draws its own arrow buttons, track and thumb, so it looks the same on every machine — including those set to overlay scrollbars.

Portal colours

The surfaces each portal paints — page background, content area and navigation — plus the one accent they share. Every value is the literal from that portal's stylesheet.
