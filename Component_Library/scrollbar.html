Scrollbar

The scroll bar on the right of the PPWR Compliance listing, reproduced from the screenshot of that page: an up arrow button, an invisible track, a rounded thumb, and a down arrow button. Every measurement below was read off the screenshot pixels, and the thumb and both arrows resolve to the same tint. Nothing else on this page.

Anatomy

Drawn to the measured sizes — the figure below is an SVG at 1:1, so it can be compared against the screenshot directly.

  1. Up arrow button — 14×14 box, a solid 9×5 triangle, apex up.
  2. Track — transparent. The card behind it shows straight through.
  3. Thumb — 9px wide, centred in the 14px gutter, fully rounded ends.
  4. Down arrow button — the same box and triangle, mirrored.

Specimen

Live, in both themes. The two buttons, the track and the thumb are all drawn by the component itself, so they appear even on a machine set to overlay scrollbars.

Dark · #94b4e6 at 26%

Scrollable region. The arrow button sits at the top of the gutter, the thumb below it, the second arrow button at the bottom.

The track never paints — what reads as a channel is the card surface behind it.

The thumb is 9 pixels wide inside a 14 pixel gutter, so it clears each edge by 2.5 pixels, with fully rounded ends.

Both arrows carry the same tint as the thumb, at the same opacity — solved from the screenshot pixels, all three landing on 26%.

Nothing is hover-gated: the bar is painted at rest, as in the screenshot.

Light · the ink twin

The same component with --gs-sb-thumb and the two arrow images swapped to the light-theme ink.

Geometry is identical — only the two colour tokens change.

Why the arrows exist. The staging stylesheet declares both scrollbar-color and a set of ::-webkit-scrollbar rules (a 6px bar with no buttons). Once Chrome sees scrollbar-color it hands the bar back to the browser — rendering the native scrollbar recoloured, arrow buttons included, and ignoring the pseudo-elements entirely. That is why the real page shows a 14px bar with arrows rather than the 6px one the CSS appears to describe. The screenshot is the truth, so this component draws those four parts explicitly instead of relying on the recolour, which would produce a button-less bar on any machine set to overlay scrollbars.
One caveat for the port. Firefox has no scrollbar pseudo-elements and no arrow buttons at all — scrollbar-color recolours track and thumb and nothing more, and no stylesheet can add the triangles. Its declaration is gated behind @supports (-moz-appearance:none), because setting it unconditionally would switch Chrome back to the native bar and undo everything above. If the arrows must be identical in all three engines, the only route is a custom JS scrollbar overlaying a hidden native one.
